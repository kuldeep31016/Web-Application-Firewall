Detection under incomplete information

Every condition is evaluated on the same held-out test URLs with the same seeded removal of information. Complete-information performance is the reference; incomplete conditions measure degradation; the mitigated condition uses the model trained with incomplete examples.

Research problem

Phishing detectors are trained and evaluated with every URL feature available. In practice some information cannot be extracted. A model that depends on one or two cues can fail when they are missing.

Research question

How does missing feature information affect the ability of a machine-learning model to detect phishing URLs, and can an appropriate missing-information handling strategy enable the model to continue detecting phishing URLs reliably?

Missing-information methodology

Features = the seven URL segments the token sequence is built from: scheme · subdomain · domain · tld · path · query · fragment.

Information is removed before tokenisation, on the same held-out test URLs, with a fixed seed: either a chosen set of segments for every URL (single / multi-feature conditions) or each segment independently with probability p ∈ {0, 10, 20, 30, 40, 50 %}.

[MISSING]://login.[MISSING].co.uk/account/verify.php?id=1

Mitigation methodology

Training with incomplete examples. A second copy of the classifier (robust) is trained on the same training split, but in every epoch each URL gets a fresh random subset of segments replaced by the [MISSING] marker (per-URL rate ~ U(0, 0.5)).

Compared strategies: none (segment blanked, baseline model) · missing_token (marker, baseline model) · augmented_training (marker, robust model).

Evaluation metrics

Per condition: accuracy, precision, recall, F1, false-positive rate, false-negative rate, ROC AUC and the confusion matrix; plus the change versus the complete-information reference and, for the mitigation, the recovery versus no handling. Feature dependency removes each segment (and optional combinations) individually.
